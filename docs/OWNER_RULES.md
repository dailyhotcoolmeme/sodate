# 오너와 일하는 방식 (2026-09-07)

> 이 문서는 «코드를 어떻게 짜느냐»가 아니라 «오너와 어떻게 일하느냐»다.
> 전부 실제로 사고가 나서 오너가 명시적으로 정한 것들이다. 지키지 않으면 같은 사고가 반복된다.

---

## 0. 가장 중요한 세 가지

### 🚨 확인 없이 손대지 않는다

오너가 무엇을 말하든 — 질문("이게 뭐야?"), 불만("~가 이상하다"), 버그 스크린샷 —
**곧바로 파일을 고치거나 배포하지 않는다.** 먼저 (1) 내가 이해한 문제를 말로 진술하고,
(2) "해"/"고쳐"/"진행해" 같은 명시적 승인을 받은 뒤에 도구를 든다.

- **"보고해봐"는 보고만 하라는 뜻이다.** 보고 중에 틀린 걸 발견해도 그 자리에서 고치지 않는다
- **읽기·조사는 승인 없이 해도 된다.** 막는 건 파일을 바꾸거나 배포하는 일이다
- **"이 정도는 안 물어봐도 되겠다"는 판단을 하지 않는다** — 그 판단이 매번 틀렸다
- 이미 "다 고쳐" 로 묶어 승인받은 범위 안이면 항목마다 다시 묻지 않는다.
  다만 **작업 중 발견한 별개 문제**는 다시 확인부터 받는다

### 🚨 해보지 않고 «된다»고 말하지 않는다

「그록으로 만들면 된다」고 해놓고 안 됐던 일이 있다. 그러고는 기록을 찾아 변명으로 썼다.

- 「된다」고 말하기 전에 **가장 작게라도 실제로 해본다.** 안 해봤으면 「해봐야 안다」고 말한다
- 실패했을 때 **기록·규칙을 인용해 변명하지 않는다.** 뭘 잘못했는지만 말한다
- **좁은 검사 하나로 «완료»를 선언하지 않는다**

### 🚨 크롤 자료는 100% 정확해야 한다

나이·가격·마감·날짜·시간이 100% 정확하지 않으면 앱은 쓸모가 없다.
100% 확신이 없으면 임의로 채우지 말고 **오너에게 확인**받는다.

---

## 1. 말하는 방식

- **항상 한국어, 항상 존댓말**
- **결론 먼저, 쉽게.** 전문용어·영어 약어를 쓰지 않는다. 오너는 개발자가 아니다
- **문서 번호·코드 식별자를 들이대지 않는다**(`715d96d`, `RULE-3` 같은 것)
- 시킨 일의 결과를 **먼저** 보고한다. 곁다리부터 늘어놓지 않는다
- 추측을 사실처럼 말하지 않는다. 확인한 것과 추정한 것을 분명히 나눈다
- 숫자를 말하기 전에 **검산**한다

## 2. 작업 방식

- **애매하면 묻는다.** 단, 답이 뻔한 건 묻지 말고 정하고 진행한다
- **"적게 시작하자"는 제안을 하지 않는다.** 처음부터 제대로 만든다
- **스스로 단계를 쪼개지 않는다**(1단계·2단계로 임의 분할 금지)
- **요청한 것만 고친다.** 시키지 않은 재설계·필드 추가를 하지 않는다
- 한 번 지시받은 것은 **같은 종류 전부에 일괄 적용**한다
- 새 화면은 **조사 → 시안 → 승인** 순서로 간다
- 명령은 60초 넘길 것 같으면 백그라운드로 돌린다
- **터미널 명령을 오너에게 시키지 않는다.** 직접 실행한다

## 3. 디자인·UI 규칙

- **sticky(화면에 붙어 따라다니는 것) 금지**
- **가로 스크롤바가 보이면 안 된다**
- **아이콘만 있는 버튼 금지** — 글자를 같이 넣는다
- **줄임말 라벨 금지**
- 로그인 상자는 **항상 화면 중앙**
- 카드 선택 표시는 **테두리만** — 체크 배지를 겹치지 않는다
- **모바일 기준으로 만들고 모바일에서 확인**한다
- **AI가 만든 티가 나는 디자인 금지**
- 저장성 동작(등록·수정·삭제)은 **화면 전체 중앙 스피너**. 버튼 안 스피너 금지
- UI 고치고 나면 **스크린샷으로 확인**하고 보고한다

## 4. 배포

- **작업이 끝나면 바로 커밋·푸시**한다. `git add -A` 로 전부 담는다
- sodate 앱은 **작업 끝나면 바로 OTA**(안드·iOS 동시)
- 이미지는 **R2 주소로** 전달한다
- **EAS 빌드는 오너 허락 없이 하지 않는다**

## 5. 절대 하지 말 것

- **업체에 "크롤링" 관련해서 묻지 않는다.** 우리가 긁고 있다는 걸 알려주는 꼴이다
- **애드센스 언급 금지**
- **법률 자문받으라는 제안 금지**
- 서브에이전트가 **스스로 배포하지 않는다**
- DB 컬럼 rename·삭제는 **클라이언트 수정·배포와 반드시 동시에**
  (순서를 어겨 게시판 전체가 안 보이는 사고가 있었다)

## 6. 이 프로젝트에서 이미 정해진 것들

물어보지 말고 그대로 따를 것.

| 주제 | 결정 |
|---|---|
| 앱 이름 | **모잇** (옛 이름 '소개팅모아'). 내부 ID `sodate` 는 영구히 그대로 |
| 닉네임 | MY 에서 한 번 설정 = 전 서비스 공용. 각 작성화면에 닉네임 칸을 두지 않는다 |
| 소셜링 소스 | 문토·트레바리·동행클럽 셋뿐. 프립·소모임 제외 |
| 여성 나이 | 에모셔널오렌지는 전 라인 «제한 없음»(2026-07-25 확인) |
| 결제 | 자체 결제·예약 시스템을 만들지 않는다. 전부 아웃링크 |
| 회원가입 | 앱에 회원가입·로그인이 없다(푸시 토큰만) |
| 상세 설명 | 크롤 텍스트를 앱에 안 쓴다. 오너가 올린 이미지 유형으로 보여준다 |
| 제휴 할인 문구 | 자유 입력(구조화하지 않는다) |
| 필터 시트 | 로컬 draft 로만 편집하고 «적용하기» 에서만 반영 |
