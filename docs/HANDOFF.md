## 1. 지금 무엇을 하고 있었나

게시판(= 앱에서는 **커뮤니티**)을 애플 4.2.2 재제출 수준으로 다듬는 중이다.
마지막 작업은 **댓글 화면에서 키보드가 올라올 때의 동작**이었고, 방금 고쳐서 오너
아이폰에 설치까지 마쳤다. **오너 확인 대기 중.**

### 방금 설치한 것 (확인 안 받음, 2026-08-01 세 번째 수정)

- 댓글 입력줄을 누르면 목록을 **키보드 높이만큼 위로 밀어 올린다**.
  누르기 직전에 보던 댓글이 입력줄 바로 위에 그대로 남게 하는 것.
- 답글(`답글` 탭) 이동은 대상 댓글이 보이는 자리로 옮긴다. "OOO님에게 답글" 라벨이
  뜨는 구조라 대상이 화면에 없으면 라벨과 화면이 따로 노는 문제가 있어 이동 자체는
  유지 — 오너가 "답글 탭하면 그 댓글로 옮겨가는 게 맞지 않냐"고 확인해 준 방향.
  ("답글 탭 시 스크롤 이동"이 다른 앱 업계 표준인지는 **확인 못 함**, 외부 조사 실패.
  이 결정은 표준 여부와 무관하게 라벨-화면 일치를 위해 내림.)

**두 번째 수정에서 놓친 것 — 오너가 지적**: 키보드가 다 올라온 "뒤"에야 화면이
움직였다. 원인은 `useKeyboardState`(→ `keyboardDidShow`)가 iOS에서 키보드 애니메이션이
**끝난 뒤**에만 값을 갱신하는 것 — 그래서 화면 이동이 키보드 rise 뒤에 순차적으로
덧붙는 것처럼 보였다. `keyboardWillShow`(키보드가 올라오기 **직전**에 오는 이벤트,
목표 높이 포함)로 바꿔서 목록 이동이 키보드 애니메이션과 같은 타이밍에 시작하도록
고쳤다(`app/app/board/[id].tsx:59-93`). 답글 탭 시 즉시 스크롤하던 것도 제거하고
같은 `keyboardWillShow` 타이밍으로 합침 — 이제 "답글 탭 → 키보드 뜨는 순간 OO님
댓글로 한 번에 이동"이 된다.

### 아직 오너가 정하기로 한 것

- **태그 묶음의 이름과 순서** — "내가 다시 얘기해줄게"라고 했다. 지금 이름은 임시.
- **관리자에서 이미지 가릴 때 파일을 공개 버킷 밖으로 옮길지** — 지금은 앱 화면에서만
  안 보이고, 주소를 직접 열면 사진이 그대로 보인다(`board-images`가 public 버킷).
  심사 전에 할지 출시 후로 미룰지 미정.
- **admin 배포** — `useAllHashtags` 1000행 제한 수정이 코드에만 있고 배포 안 함.

## 3. 외부 조사로 확인된 사실 (근거 있음)

추측으로 만들다 여러 번 뒤집혔다. **아래는 출처가 확인된 것만.**

### 글 작성 화면 (10개 앱 조사)

- **등록 버튼**: 상단 우측 = 네이버 카페(`등록`)·당근 동네생활(`완료`)·에브리타임(`완료`)·
  블라인드(`Post`)·X(`Post`)·페이스북(`Post`). 하단 풀폭 = 인스타(`공유`)·당근 중고거래
  (`작성 완료`). **하단 풀폭인 둘은 성격이 다르다** — 인스타는 마지막 단계, 당근 중고거래는 폼.
- **사진 첨부**: **전부 화면 맨 아래 도구줄**(키보드가 올라오면 그 위). 본문 아래에
  인라인 버튼을 둔 앱은 **한 곳도 없다.**
- **키보드가 올라올 때**: 상단바 고정, 도구줄이 키보드 위에 밀착, **그 사이 본문 영역만
  좁아진다**(블라인드 공식 블로그 키보드 활성 스크린샷).

### 댓글 화면에서 키보드가 올라올 때 (화면녹화 프레임 비교)

| 앱 | 판정 | 근거 |
|---|---|---|
| 인스타그램 iOS | **내용 안 움직임** | https://youtu.be/3fhN9BinJ9U (21.3초 ↔ 22.3초) |
| 레딧 iOS | **내용 안 움직임** | https://youtu.be/FebfyDHt4aA (23.1초 ↔ 25.5초) |
| 레딧 Android | 전체화면 작성 화면으로 전환 | https://youtu.be/J-nnbhTwImU (28.8초 ↔ 29.0초) |
| 유튜브·페북·X·당근·네이버 카페·에브리타임·블라인드 | **확인 못 함** | 판정 가능한 화면녹화 없음 |

**우리는 일부러 다르게 간다.** 그 앱들은 댓글이 화면/시트 맨 위부터 시작해서 창이 줄어도
여러 개가 남는다. 우리는 위에 제목·본문·추천·댓글헤더가 얹혀 있어 댓글 영역이 약 450pt인데
키보드가 336pt를 먹어 **한 개만 남는다**(실측). 그래서 목록을 밀어 올리는 쪽을 택했다.

### 그 밖에 확인된 것

- **키보드 닫기 버튼은 확인된 모든 앱에 없다.** 넣지 않는다.
- 답글 들여쓰기는 **1단계**, 대댓글에는 답글 버튼이 없다(에브리타임·블라인드).
- 네이버 카페 도구줄 구조: 아래 = 기본 도구 막대(카메라·T·스티커·태그·인용),
  그 위 = 속성 도구 막대(서체·크기·정렬·**B**·인용·*I*).

## 4. 하지 말아야 할 것 (여러 번 지적받음)

- **짐작으로 UI를 만들지 않는다.** 모르면 외부 조사하고, 못 찾으면 그렇게 말한다.
- **파킨온을 참고하지 않는다.** 거기도 최악이라고 오너가 명시했다.
- 값(여백·글자 크기)을 새로 지어내지 않는다. **기존 클래스·토큰을 재사용**한다.
  (필터 버튼을 지역 칩과 다르게 만들었다가 지적받음)
- 확인 안 된 것을 사실처럼 말하지 않는다. 조사 에이전트에도 "확인 못 함"을 쓰게 한다.
- 화면을 못 본 채 "고쳤습니다"라고 하지 않는다.
