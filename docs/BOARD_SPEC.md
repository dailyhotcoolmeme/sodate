# 게시판 사양

> 2026-07-31 오너와 확정. 이전 초안(`심야톡`)은 이름부터 일부 결정까지 작성자가 임의로
> 붙인 것이 섞여 있어 폐기하고 새로 씀.

## 왜 만드는가

애플이 4.2.2로 두 번 반려했다. 두 번째 회신(2026-07-31)의 문장:

> the app still only includes links, images, or content aggregated from the Internet
> with limited or no native functionality ... it does not sufficiently differ from a
> web browsing experience

즉 **앱 안에서 콘텐츠가 만들어지지 않는다**는 판단이다. 조건 알림·후기·관심 목록을
근거로 반박했지만 받아들여지지 않았다. 게시판은 이 지적을 정면으로 해소하기 위한 것이다.

같은 회신에 iPad 지적도 있었다. 이는 게시판과 별개로 처리한다.

## 진입 — 톱바 전환

하단 탭은 만들지 않는다(오너 확정: 현재 디자인에 대한 반응이 좋음). 톱바 가운데에서
일정과 게시판을 오간다.

```
[소개팅모아]  (토글: 꺼짐)  🔔·☰      ← 일정
[소개팅모아]  (토글: 켜짐)  🔔·☰      ← 게시판
```

✅ **2026-08-07, 심사 통과 후 오너 지시로 토글로 교체 완료** — 켜짐=커뮤니티, 꺼짐=소개팅
(`components/TopBar.tsx`). 심사 중엔 "게시판 글자를 유지해 심사자가 눌러보게 할 것"이었으나
그 조건(통과)이 이미 충족돼 지금은 텍스트 없는 토글이 정본이다. 알림 벨도 같은 날 햄버거
메뉴 밖으로 빼서 톱바에 상시 노출(안 읽음 개수 배지 포함)로 바뀌었다.

⚠️ **다음 네이티브 빌드가 새로 심사를 받을 때 이 부분이 다시 문제될 수 있다** — 토글만
있으면 심사자가 커뮤니티 기능 자체를 못 찾고 안 눌러볼 수 있음. 그런 재제출 앞두고는
이 문서의 예전 경고(텍스트 유지)를 다시 검토할 것.

- 필터 아이콘은 일정에서만. 게시판에는 그 자리에 **검색**(제목+본문).
- 알림 벨은 전역이라 양쪽 모두, 톱바에 상시 노출.
- 햄버거는 구성을 바꾸지 않고 **첫 줄만 화면에 따라 다르게** 한다.

| 일정일 때 | 게시판일 때 |
|---|---|
| 내가 쓴 후기 → 후기 모아보기의 `내 후기` 탭 | 내가 쓴 글 |
| 후기 모음 / 관심 모임 / 알림 설정 / 내 정보 / 설정 | (동일) |

## 화면

목록 · 상세 · 글쓰기 세 개만 새로 만든다.

### 목록
- 한 페이지 20개, **번호 페이지 방식**(무한 스크롤 아님).
  `« ‹ 6 7 8 9 10 › »` — 현재 페이지를 가운데, 양끝으로 처음·마지막 이동.
- 한 줄 구성: 제목 + `[댓글수]` + 새 글 배지, 아랫줄에 `닉네임 시각 · 추천 n · 비추 n`
- **추천 10 이상 → 제목 굵게. 비추 10 이상 → 제목 흐리게.** 흐려질 뿐 지워지지 않는다.
- 정렬은 최신순 하나만. 인기글 목록은 글이 쌓인 뒤에 검토.

### 상세
- 제목 / 닉네임 · 작성시각 / 본문
- **추천 · 비추** 버튼(기기당 글마다 1회, 다시 누르면 취소)
- 내 글이면 **수정 · 삭제**, 남의 글이면 **신고**
- 댓글 목록 + 입력. **대댓글은 한 단계까지.** 댓글도 수정·삭제 가능.

### 글쓰기
- 닉네임 + 제목 + 본문 (+ 이미지)
- 닉네임은 후기와 같은 방식으로 기기에 기억해 다음 작성 시 자동 입력.
  **성별은 받지 않는다** — 익명 게시판에서 성별 시비를 만들 이유가 없다.

## 확정 사항

| 항목 | 결정 |
|---|---|
| 작성자 | 닉네임만(성별 없음). 기기에 기억 |
| 댓글 | 필수. 대댓글 1단계. 수정·삭제 모두 |
| 댓글 추천·비추 | 없음(글에만) |
| 진하게 / 흐리게 | 추천 10 / 비추 10 |
| 글 자동 숨김 | 신고 5건 |
| 이미지 자동 가림 | 신고 **2건**(초기값) |
| 도배 방지 | 글 30초 · 댓글 10초 간격 |
| 조회수 | 쌓아두되 화면에서는 감춤. 나중에 켜면 그때까지 숫자가 그대로 |
| 목록 | 페이지 방식, 한 페이지 20개 |
| 글자 수 | 제목 60자 / 본문 1만 자 / 댓글 1000자 |
| 댓글 알림 | 1차 미포함. 게시판이 도는 것을 보고 검토 |
| 게시판 개수 | 하나. 말머리·공지·제휴 없음 |
| 이름 | **미정** — 화면에 넣기 전까지 정할 것 |

### 글자 수를 두는 이유

제목은 목록에서 한 줄로 보여주므로 60자가 넘으면 말줄임만 남는다.
본문 1만 자는 길이 제한이라기보다 사고 방지다 — 익명이라 누군가 수십만 자를 붙여넣으면
목록·상세 렌더링이 버벅이고 DB가 낭비된다. 1만 자면 장문도 다 들어가 사용자는 제한을
느끼지 못한다.

## 이미지

- **올리면 바로 보인다.** 승인 후 노출 방식은 쓰지 않는다 — 심사자가 사진을 붙였는데
  admin 승인 전까지 안 보이면 "첨부가 동작하지 않는다"로 판단한다. 기능 부족으로
  반려당한 상황에서 치명적이다.
- 신고 **2건**이면 이미지를 가리고 그 자리에 **`이미지 검수 중`** 오버레이를 띄운다.
  글은 그대로 남는다. 가려진 이유가 보여야 작성자도 보는 사람도 납득한다.
- 임계치는 코드 수정 없이 바꿀 수 있게 둔다. 사용자가 늘면 5건으로 올린다.

### 왜 2건인가 (글은 5건인데)

사용자가 많으면 음란물은 금방 신고가 터진다. 그러나 게시판을 막 연 시점에는 그 사용자가
없다. 하루 방문자가 수십 명이면 5건이 모이는 데 몇 시간~며칠이 걸리고 그동안 계속
노출된다. 하필 그때 심사자가 보면 1.2 위반으로 더 무거운 반려가 된다.
정상 사진이 2건에 가려지는 오작동은 admin에서 풀면 되지만, 음란물이 몇 시간 노출되는
것은 되돌릴 수 없다.

### 딸려오는 절차

- 사진 접근 권한 추가 → 심사 노트에 용도 기술
- UGC + 이미지로 **연령 등급 재평가** 대상이 될 수 있음

## 금칙어 필터

후기(`supabase/functions/reviews/index.ts`)의 목록을 재사용하되 **게시판용으로 보강한다.**

현재 목록:
```
씨발 시발 씨빨 개새끼 새끼 병신 지랄 좆 섹스 보지 자지
엠창 느금 니미 창녀 창놈 걸레 미친년 미친놈 썅 스팸 광고문의
fuck shit bitch asshole porn sex
```
공백 제거 + 소문자 변환 후 포함 검사라 `씨 발`도 걸린다.

⚠️ 이대로는 익명 자유게시판에 약하다. 두 가지가 빠져 있다.
1. **초성·변형** — `ㅅㅂ`, `시1발`, `ㅄ` 등을 못 잡는다
2. **홍보 글** — 카톡 아이디, 오픈채팅 링크, 전화번호를 전혀 못 막는다

보강 목록은 별도로 정리해 오너 확인 후 반영한다.

## 재사용할 기존 자산

- `owner_token` — 후기의 익명 소유권 토큰(기기별). 글·댓글·추천·신고 모두 이걸로 식별
- `ReportSheet` / `report_count` — 신고 UI와 집계
- `ReviewSheet` — 작성 시트 UI 패턴
- admin `Reviews.tsx` — 관리 화면 패턴
- R2(`sodate-media`) + `/api/upload` — 이미지 저장
- 후기 닉네임 저장(`reviewIdentity.ts`) — 게시판 닉네임도 같은 방식

## admin 관리

후기 관리 화면과 같은 모양으로 만든다. 없으면 신고가 들어와도 처리할 수 없고,
애플 1.2가 요구하는 24시간 내 대응을 못 지킨다.

- 글·댓글 목록, 숨김, 삭제
- 이미지 가림 해제
- **기기 토큰 차단** — 악성 사용자 차단(1.2 필수 요건)

## 애플 1.2 (사용자 생성 콘텐츠) 대응

| 요건 | 어떻게 |
|---|---|
| 부적절한 콘텐츠 필터링 | 금칙어 필터(보강판) |
| 신고 기능 | 글·댓글 신고 |
| 악성 사용자 차단 | admin에서 기기 토큰 차단 |
| 게시된 연락처 | admin@ourmine.co.kr (이미 있음) |
| 신고 후 24시간 내 처리 | admin 관리 화면 + 운영 약속 |

## 콜드 스타트

오너 후배가 유행 콘텐츠 중심으로 글을 꾸준히 올리기로 함.

- **심사 제출 전 글이 스무 개 정도는 있어야 한다.** 서너 개면 "만들다 만 기능"으로 보인다.
- 퍼온 사진은 피할 것. 저작권 신고가 들어오면 앱 전체가 걸린다.

## 만드는 순서

1. DB 테이블(글·댓글·추천·신고·차단)
2. 서버 함수(작성·수정·삭제·추천·신고) — 후기 Edge Function 패턴
3. 앱 화면(목록·상세·글쓰기·검색) + 톱바 전환
4. admin 관리 화면
5. iPad 대응(별건)
6. 심사 노트 재작성 — **어디를 눌러 무엇을 하는지 단계별로.** 이번 회신에서는
   기능을 나열했지만 "어디를 눌러라"가 빠져 있었다.
