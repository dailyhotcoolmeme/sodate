## 1. 사용자 후기 남기기 (로그인 없는 환경)
- **핵심 제약**: 앱에 로그인이 없음(푸시 토큰만). 그런데 사용자가 **본인이 남긴 후기를 수정/삭제**할 수 있어야 함 → 소유권 식별 대안 필요.
- **공존 요구**: 지금 있는 후기(크롤링된 네이버/인스타 후기 = review_naver, review_instagram)는 **유지**하면서, 사용자 직접 작성 후기가 **공존**하는 방식 고민 필요.
- 검토 필요 사항(미결):
  - 소유권 식별 방식 — 기기 푸시 토큰 기반? 익명 로컬 시크릿? 간편 인증(휴대폰/카카오만 후기용)?
  - 크롤 후기 vs 사용자 후기 구분·표시·정렬
  - 스팸/악용 방지(로그인 없으니 취약)
- 상태: **설계 필요. 미착수.**

## 2. 호스트 반복 일정 일괄 등록 (플랫폼형 업체)
- 일부 업체는 **업체 자체가 플랫폼 성격**이고, 그 안에서 **모임을 운영하는 호스트**가 있음.
- 이 호스트들은 **매주 일정한 모임**을 운영 → **정해진 반복 일정을 한 번에 등록**하는 방식 필요(매번 개별 등록 X).
- 상태: **참고만. 아직 착수 X.** (오너가 "일단 참고만 하고 있어"라고 함)
