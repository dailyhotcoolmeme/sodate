# 앱 업데이트(OTA)를 Cloudflare + R2 로 직접 운영하기

> 2026-09-14 조사. **모입찌(mozzzi) 등 다른 프로젝트에 그대로 전달하기 위한 문서.**
> 여기 적힌 «확인함»은 실제로 해 본 것이고, «안 해봄»은 아직 안 해 본 것이다.
> 안 해 본 것을 «된다»고 말하지 말 것.

---

## 1. 왜 옮기나

Expo(EAS Update)는 **받아간 횟수**에 한도를 건다. 무료는 **월 1,000회**다.
그런데 이 한도는 **프로젝트별이 아니라 «계정» 단위**다.

- `dailyhotcoolmeme` 계정에 프로젝트 **8개**가 붙어 있다
  (dangoljip · dongne · myamen · ootd · parkinon · sodate · toolshere · youngnakchurch)
- 한 프로젝트가 많이 쓰면 **다른 프로젝트가 막힌다**

**«받아간 횟수»가 정확히 무엇인지 실측으로 확인했다(중요):**

| | 모잇 이번 달 |
|---|---|
| 앱이 켜져서 «새 거 있어?» 물어본 횟수 | **782회** |
| Expo 가 센 횟수 | **149회** |
| 전송량 ÷ 149 | 1회당 11.2MB = 번들 전체 크기 |

→ **«물어보기»는 안 센다. «실제로 내려받은 것»만 센다.**
→ 그래서 «무음 푸시로 배포 순간에만 깨우기» 같은 방식은 **이 한도를 못 줄인다.**
   그건 «물어보는 횟수»를 줄이는 것인데, 물어보기는 애초에 공짜다.
   (웹뷰 앱은 다르다 — 웹만 고치면 앱이 아무것도 안 받으므로 그쪽은 효과가 있다.)

---

## 2. 옮기면 얼마나 여유로워지나 (실측)

Cloudflare 유료($5)는 **월 1,000만 요청 포함**, 초과분은 100만 회당 약 $0.30.
R2 는 **내려받기(egress) 요금이 0원**이다.

이 CF 계정도 여러 프로젝트가 같이 쓴다 — 워커 **26개**가 붙어 있다.
7일 실측: 하루 평균 **13,348회** → 한 달 약 **40만 회** = 포함량의 **4%**.

한 사람이 한 번 업데이트받을 때 요청은 **2회**(물어보기 1 + 번들 1).
에셋은 이미 받은 것을 다시 안 받는다.

| 설치 대수 | 월 4회 배포 | 늘어나는 요청 | 합계(현재 40만 + α) |
|---|---|---|---|
| 1,000대 | 4,000회 받아감 | 8,000회 | 41만 (4%) |
| 5,000대 | 20,000회 | 4만 | 44만 (4.4%) |
| 30,000대 | 12만 회 | 24만 | 64만 (6.4%) |

→ **한도가 Expo 대비 1만 배 크다.** 설치 30만 대쯤 돼야 한도가 보인다.
→ 단, 같은 계정의 다른 프로젝트가 폭증하면 같이 영향을 받는다.

## 3. 구조 — 이미 돌아가는 것과 똑같다

핵심: **새로 만드는 게 아니라, 지금 «앱 사진»을 내려주는 구조를 그대로 쓴다.**

지금 사진은 이렇게 나간다(실측: 0.67초 / 103KB 정상 응답, Cloudflare 처리):

```
앱 → sodate-admin.pages.dev/media/{key} → R2(sodate-media) → 사진
```

처리 코드는 `admin/functions/media/[[path]].ts` 20줄짜리다.
업데이트도 같은 방식으로, **파일만 사진 대신 앱 화면 덩어리**로 바꾸는 것이다.

```
[배포할 때]
  npx expo export  →  번들 + 에셋 83개  →  R2 에 업로드

[앱이 켜질 때]
  앱 → (우리 주소)/api/manifest → 「새 거 있어?」 에 답해주는 함수
                                 → R2 에 있는 파일들의 주소·지문을 알려줌
  앱 → (우리 주소)/ota/{key}    → R2 에서 파일 전달
```

## 4. 앱이 요구하는 규격 (실측으로 받아낸 것)

**요청**: 앱이 이런 헤더를 보낸다
```
expo-platform: android | ios
expo-runtime-version: 1.1.0
expo-channel-name: production
expo-protocol-version: 1
Accept: multipart/mixed
```

**응답**: `multipart/mixed` 3덩어리 + 헤더 `expo-protocol-version: 1`

| 덩어리 | 내용 |
|---|---|
| `manifest` | application/json — 아래 구조 |
| `extensions` | application/json |
| (세 번째) | 짧은 마무리 |

`manifest` 최상위 항목 (실측):
```
id, createdAt, runtimeVersion, launchAsset, assets, metadata, extra
```
- `launchAsset` 키: `hash, key, contentType, url`
- `assets[]` 키: `hash, key, contentType, fileExtension, url` — 모잇 기준 **83개**

`npx expo export` 가 만드는 `metadata.json` 에 번들 경로와 에셋 83개 목록이 그대로 들어 있다.
**개수가 Expo 서버 응답과 정확히 일치하는 것을 확인했다.**

## 5. 지금까지 확인한 것 / 안 해본 것

| 항목 | 상태 |
|---|---|
| 업데이트 파일을 우리 손으로 만들기 | **확인함** — `npx expo export` 로 번들 6.1MB + 에셋 83개 생성 |
| R2 에 올리고 읽기 | **확인함** — 시험 파일 올렸다 지움 |
| R2 파일을 공개 주소로 내려주기 | **확인함** — 사진이 이미 이 방식으로 서비스 중 |
| 앱이 요구하는 응답 규격 | **파악함** (위 4항) |
| **「새 거 있어?」에 답해주는 함수** | **🚨 안 만들어 봄** |
| **실기기에서 업데이트가 실제로 오는지** | **🚨 안 해봄** |

**마지막 두 개를 해보기 전에는 «된다»고 말하면 안 된다.**
형식이 조금만 어긋나도 앱이 업데이트를 못 받거나 실행 중 멈출 수 있다.

## 6. 가장 중요한 제약 — 되돌리기

> **업데이트 받는 주소(`app.json` 의 `updates.url`)는 OTA 로 못 바꾼다.
> 앱 안에 박히는 값이라 «새 빌드 + 스토어 제출»이 있어야 바뀐다.**

이게 위험이자 안전장치다.

- **위험**: 잘못 만든 채로 스토어에 내보내면, 되돌리는 데도 새 빌드·심사가 필요하다
- **안전**: 이미 깔린 앱은 계속 Expo 를 본다. 새 빌드를 받은 사람부터 천천히 넘어간다.
  **기존 사용자는 영향이 없다**

### 그래서 반드시 이 순서로

1. Cloudflare 쪽 업데이트 서버를 만든다 — 앱은 안 건드린다
2. 명령줄로 직접 불러 **응답이 Expo 것과 같은지 대조**한다
3. **시험용 빌드 하나**를 만들어 오너 폰에만 깔고, 실제로 업데이트가 오는지 본다
4. 잘 되면 정식 빌드에 반영해 스토어 제출
5. 문제가 생기면 주소 한 줄을 되돌리고 다시 빌드

**3번에 EAS 빌드가 필요하다 — 오너 허락 없이 하지 않는다.**

---

## 7. 모입찌(mozzzi)에 적용할 때 다른 점

- 모입찌는 아직 스토어 출시 전이다. **출시 «전»에 이 주소로 맞춰두면
  나중에 되돌릴 일 자체가 없다** — 지금이 옮기기 가장 좋은 시점이다
- 에셋 개수·번들 크기는 프로젝트마다 다르다. `npx expo export` 로 직접 확인할 것
- R2 버킷은 프로젝트별로 나누는 게 좋다(모잇은 `sodate-media`, OOTD 는 `ootd-media` 사용 중)
- `runtimeVersion` 이 다르면 다른 업데이트를 받아야 한다. 서버가 이 값으로 갈라줘야 한다

## 8. 참고 — 검토했다가 접은 방식

| 방식 | 왜 접었나 |
|---|---|
| 배포 횟수를 줄인다 | 오너 거부. 필요할 때 못 고치는 건 해결이 아니다 |
| 바뀐 부분만 받게 한다 | 오너 거부 |
| 무음 푸시로 배포 순간에만 깨우기 | **이 앱엔 효과 없음.** 줄이는 건 «물어보기»인데 그건 애초에 공짜다(1항 참고). 웹뷰 앱(마이아멘)은 효과가 있다 |
