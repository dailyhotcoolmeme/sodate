# 입력 화면 공통 규칙

> 2026-08-01 오너 확정. 화면마다 다르게 만들다 같은 문제가 반복돼(키보드 가림, 스피너,
> 닉네임) 규칙으로 못박는다. 입력이 있는 화면은 예외 없이 여기에 맞춘다.

## 1. 키보드 가림은 라이브러리로 푼다

`react-native-keyboard-controller` 를 쓴다. **직접 좌표를 재서 스크롤하는 코드를 쓰지 않는다.**

- RN 기본 `KeyboardAvoidingView` 는 **여러 줄 입력에서 동작하지 않는다.** 알려진 미해결
  버그다(react-native#16826). 이걸 손으로 우회하려는 시도가 계속 실패했다.
- 폼(스크롤 있는 화면) → `KeyboardAwareScrollView`
- 화면 아래 고정 입력줄(댓글 등) → `KeyboardStickyView`
- 앱 루트에 `KeyboardProvider` 가 있어야 동작한다(`app/_layout.tsx`).

**키보드를 닫을 때는 `KeyboardController.dismiss()` 를 쓴다.** RN 기본
`Keyboard.dismiss()` 나 `ref.blur()` 로는 닫히지 않는다 — 이 라이브러리가 키보드를
직접 쥐고 있기 때문이다. 2026-07-31 에 이걸 모르고 세 번을 헛짚었다.

```ts
import { KeyboardController } from 'react-native-keyboard-controller'
await KeyboardController.dismiss()   // 포커스까지 떼고, 실제로 닫힐 때까지 기다린다
```

등록 같은 동작에서는 **닫히길 기다린 다음에** 스피너를 띄운다. 스피너
(`LoadingOverlay`)가 `Modal` 이라, 포커스를 쥔 채로 Modal 이 열리면 닫힐 때 그 입력칸으로
포커스를 되돌려 키보드가 다시 올라온다.

## 2. 주 동작은 화면 아래 고정 버튼 — `components/BottomCTA.tsx`

2026-07-31 외부 조사로 확정. 상단 내비게이션 바에 두는 안, 키보드 위에 '등록' 글자만
얹는 안은 둘 다 폐기했다.

- **등록·저장 같은 주 동작은 화면 아래에 고정된 전체너비 버튼으로 둔다.** 키보드가
  올라오면 그 위로 따라 올라온다(`KeyboardStickyView`).
- 근거
  - 토스 디자인 시스템 `BottomCTA`: "보통 페이지 하단에 항상 고정되어 있어서, 긴
    스크롤이나 **키보드 입력 시에도** 손쉽게 접근할 수 있어요."
  - 당근 Seed Design 폼 화면 설계 예시: 앱바(뒤로가기+제목) → 내용 → **BottomCTA(등록)**.
    앱바에는 주 동작을 두지 않는다.
  - 엄지 도달 범위 실측(Steven Hoober, 1,333명): 한 손 사용 49%, **화면 위쪽 모서리가
    가장 안 닿는 구간**. 주 동작은 아래쪽에.
- **글자만 얹지 않는다.** 채워진 버튼이어야 누를 것으로 보인다.
- **제출 버튼을 스크롤 안에만 두지 않는다.** 키보드가 덮는다.
- 예외: 댓글처럼 화면 아래 붙박이 입력줄은 보내기 버튼을 입력칸 옆에 둔다
  (메시지·카카오톡과 같은 모양).

## 2-1. 서식 도구는 만들지 않는다

리액트 네이티브 입력칸은 글자마다 다른 서식을 줄 수 없다. 흉내내면 본문에 `**` 같은
기호가 그대로 박힌다. 진짜 WYSIWYG 은 웹뷰 에디터를 얹어야 가능하고(Expo 공식 문서
Edit rich text), 커뮤니티 게시판에 그만한 무게를 들이지 않는다. 당근 동네생활도
글자와 사진만 받는다. **글자 + 사진이 표준이다.**

## 3. 진행 표시는 화면 중앙 오버레이만 — `components/LoadingOverlay.tsx`

- 버튼 안에 스피너를 넣지 않는다.
- 배경을 흐리게 덮고 가운데에 스피너를 띄운다.
- 저장·업로드·등록 등 기다림이 생기는 모든 동작에 붙인다.

## 4. 닉네임은 가장 최근 값을 물고 간다

후기 작성과 같은 방식이다.

- 입력칸은 **그대로 보여준다**(숨기거나 한 번만 받는 식으로 바꾸지 않는다).
- 열 때 마지막에 쓴 닉네임이 자동으로 채워져 있다.
- 거기서 바꾸면 그 값이 다음부터 기본값이 된다.
- 저장소는 후기와 공유한다(`lib/reviewIdentity.ts` 의 `getLastNickname`/`setLastNickname`).

## 5. 입력칸 정렬

- 여러 줄로 늘어나는 칸 **옆에** 다른 입력칸을 두지 않는다. 늘어날 때 높이가 어긋난다.
  (댓글칸 옆에 닉네임칸을 뒀다가 지적받음 — 닉네임을 윗줄로 뺐다.)
- 나란히 둬야 하면 높이를 고정하거나 위아래로 나눈다.

## 적용 현황

| 화면 | 상태 |
|---|---|
| 게시판 글쓰기 | 적용 — 등록은 화면 아래 고정 CTA, 서식 없음 |
| 게시판 상세(댓글) | 적용 |
| 후기 작성 시트 | **미적용** — 직접 만든 키보드 추적 코드가 남아 있다 |
| 신고 시트 | **미적용** — 직접 만든 키보드 추적 코드가 남아 있다 |
| 알림 설정 | 입력 없음 |

후기 작성 시트는 순차적으로 이 규칙에 맞춘다.
