# 입력 화면 공통 규칙

> 2026-08-01 오너 확정. 화면마다 다르게 만들다 같은 문제가 반복돼(키보드 가림, 스피너,
> 닉네임) 규칙으로 못박는다. 입력이 있는 화면은 예외 없이 여기에 맞춘다.

## 1. 키보드 가림은 라이브러리로 푼다

`react-native-keyboard-controller` 를 쓴다. **직접 좌표를 재서 스크롤하는 코드를 쓰지 않는다.**

- RN 기본 `KeyboardAvoidingView` 는 **여러 줄 입력에서 동작하지 않는다.** 알려진 미해결
  버그다(react-native#16826). 이걸 손으로 우회하려는 시도가 계속 실패했다.
- 폼(스크롤 있는 화면) → `KeyboardAwareScrollView`
- 화면 아래 고정 입력줄(댓글 등) → `KeyboardStickyView`
- 앱 루트에 `KeyboardProvider` 가 있어야 동작한다(`app/_layout.tsx`).

## 2. 주 동작은 상단 내비게이션 바에, 키보드 위는 도구 자리

애플 휴먼 인터페이스 가이드라인(Navigation bars / Text input) 기준이다.
2026-07-31 오너 지적("누가 키보드 바로 위에 등록 글자로 등록하게 하냐") 후 조사해 고쳤다.

- **주 동작(등록·완료·저장)은 상단 내비게이션 바 오른쪽에 둔다.** `TopBar` 의
  `rightAction` 이 그 자리다. 키보드 위에 '등록' 글자를 얹지 않는다 — 그런 앱은 없다.
- **키보드 위 액세서리는 서식 도구·첨부 같은 입력 보조 자리다.** 가이드라인이 드는
  예가 메일 앱의 서식 도구 줄이다. 아이콘만 쓰고 테두리 상자를 두르지 않는다.
- **아이폰 키보드에는 닫기 키가 없다.** 액세서리 줄 오른쪽 끝에 아래꺾쇠(`chevron-down`)를
  둬서 내린다. 글자로 '키보드 닫기'라고 쓰지 않는다.
- **제출 버튼을 스크롤 안에만 두지 않는다.** 키보드가 덮는다.
- 예외: 댓글처럼 화면 아래 붙박이 입력줄은 보내기 버튼을 입력칸 옆에 둔다
  (메시지·카카오톡과 같은 모양). 이건 내비게이션 바 자리가 아니다.

## 3. 진행 표시는 화면 중앙 오버레이만 — `components/LoadingOverlay.tsx`

- 버튼 안에 스피너를 넣지 않는다.
- 배경을 흐리게 덮고 가운데에 스피너를 띄운다.
- 저장·업로드·등록 등 기다림이 생기는 모든 동작에 붙인다.

## 4. 닉네임은 가장 최근 값을 물고 간다

후기 작성과 같은 방식이다.

- 입력칸은 **그대로 보여준다**(숨기거나 한 번만 받는 식으로 바꾸지 않는다).
- 열 때 마지막에 쓴 닉네임이 자동으로 채워져 있다.
- 거기서 바꾸면 그 값이 다음부터 기본값이 된다.
- 저장소는 후기와 공유한다(`lib/reviewIdentity.ts` 의 `getLastNickname`/`setLastNickname`).

## 5. 입력칸 정렬

- 여러 줄로 늘어나는 칸 **옆에** 다른 입력칸을 두지 않는다. 늘어날 때 높이가 어긋난다.
  (댓글칸 옆에 닉네임칸을 뒀다가 지적받음 — 닉네임을 윗줄로 뺐다.)
- 나란히 둬야 하면 높이를 고정하거나 위아래로 나눈다.

## 적용 현황

| 화면 | 상태 |
|---|---|
| 게시판 글쓰기 | 적용 — 등록은 톱바, 키보드 위는 서식 도구 |
| 게시판 상세(댓글) | 적용 |
| 후기 작성 시트 | **미적용** — 직접 만든 키보드 추적 코드가 남아 있다 |
| 알림 설정 | 입력 없음 |

후기 작성 시트는 순차적으로 이 규칙에 맞춘다.
