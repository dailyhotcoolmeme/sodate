# 가격 재검증 시간 초과 수정

## 확인한 원인

10/29 아침 정기 수집 40784165426은 수집 자체는 성공했지만, 후속 가격 점검이
프립 전체 상품을 다시 수집하다 8분 제한에 걸렸다. 기존 코드는 업체별 6개 가격을
비교한다고 해놓고 실제로는 전체 scrape()를 먼저 호출해 모든 상품·회차를 조회했다.

## 변경

- 프립: DB 표본의 정확한 상품/회차 URL을 먼저 고르고, 해당 회차 옵션만 조회한다.
  기존 가격 파서·지점별 옵션 분리·URL 식별자를 재사용한다.
- 문토: 표본의 공식 상세 API에서 단일 price를 조회한다. 0원도 유효하다.
  전체 카테고리 목록과 참가자 정보를 다시 조회하지 않는다.
- 모드파티: 전체 상품 27개를 순회하던 것을 표본 상품 ID로 먼저 제한한다.
  일반 수집은 기본 인자로 이전처럼 전체 상품을 확인한다.
- 조회 0건 또는 일부 표본 미조회는 WARN으로 명시하며 검증 성공으로 세지 않는다.
- 일반 scrape()/run() 및 마감 갱신 주기는 변경하지 않는다. 표본 경로는 저장하지 않고
  collection_complete=false, DELETE_STALE=false로 둬 전체 수집 자료로 오용하지 않는다.
- 전용 Price Accuracy Recheck는 정기 점검의 check_nonimweb_live()를 그대로 사용한다.
  기존 Supabase/모드파티 시크릿만 사용하며 Apify 실행이나 데이터 쓰기는 없다.

## 검증

- 전체 크롤러 테스트 179개 통과. 프립 표본은 대상 회차 옵션만 조회하고,
  일반 파서는 여전히 모든 회차를 조회하는 회귀 검사 포함.
- 40792230596: 원본 대조 함수 약 3분 17초에 끝남. 프립/문토 포함 7개 업체
  각 6건, 총 42건 가격 일치. 모드파티는 전용 작업의 로그인 환경 누락으로
  0건 WARN을 내고 실패했다. 완료를 숨기지 않고 기존 시크릿 연결 후 재검증한다.
- 워치독 40791184152: 긴급 0 / 운영 11. 상세 이미지 미분류 40→45세트.
- Gmail 4계정에서 10/29 한국시간 도착 관련 메일 없음.

최종 확인:
- 40792804084는 모드파티 전체 27상품을 순회해 지연됨을 재현한 뒤 진단 작업만 취소했다.
- 모드파티 표본 검증 40793645643 성공. 대상 상품 6개, 가격 대조 6건 일치,
  검증 함수 00:23:24~00:24:38 UTC(약 74초), PRICE_RECHECK_COMPLETE 출력.
- 앞선 7업체 42건과 합해 8업체 48건 원본 가격 일치. DB 수정/삭제/유료 호출 없음.
- 최종 CI 40793628257 성공(앱·크롤러·명시적 권한 검사).
- 정기 후속 경로도 동일한 check_nonimweb_live 함수를 사용한다. 이 함수의 실제 원본
  대조를 확인했으며, 전체 정기 워크플로의 다음 실행 결과는 계속 감시한다.
