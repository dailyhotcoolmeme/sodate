## 변경과 안전 조건

- 한 판독에서라도 명시적인 AM/PM을 읽으면 보정을 재시도한다.
- 보정으로도 일정을 읽지 못하면 원본 이미지를 자동 레이아웃(PSM 3)과
  흩어진 텍스트(PSM 11) 방식으로 각각 읽는다. 로컬 실제 이미지의 두 방식은
  모두 2026-11-21 14:30/언주역을 반환했다.
- 최종 두 결과의 날짜/시각/역이 모두 일치해야 한다. 앞선 판독에서 확정한
  값과 충돌하면 거부한다. 이미지 사이에서 항목을 조합하지 않는다.
- 재시도 판독의 가격은 저장하지 않는다. 무료 로컬 Tesseract만 사용한다.
- 진단 로그는 게시물 ID와 날짜/시각/역의 정규식 결과만 기록한다.
  서명 이미지 URL이나 포스터 본문은 로그에 남기지 않는다.
- `DELETE_STALE=False`, `PRESERVE_MISSING_PRICES=True`와 기존 verified 보호
  저장 경로를 유지한다. 기존 오너 확인 10/31 13:30 일정은 수정하지 않는다.
- 회귀 테스트 203개 통과. 별도 유료 액터 실행 없이 `yeonsoop_replay=true`로
  18시간 이내 기존 정기 수집 자료를 정상 저장 경로에서 재검증한다.

## 실제 저장 결과와 남은 문제

- 서버 실행 `42931518820`에서는 공식 프로필 조회도 HTTPStatusError로 실패했다.
  서버 자동 수집 복구는 **미완료**다. HTTP 상태 코드를 URL 없이 기록하도록 보완했다.
- 원본 조회가 되는 오너 맥에서 같은 코드로
  `cd crawler && .venv/bin/python -m scrapers.yeonsoop --reuse-last-run`을 실행했다.
  Apify 액터 POST 없이 기존 결과를 재사용했고 실제 1건 파싱, 신규 1/업데이트 0이다.
- DB 행 `c7e7b26b-a3a5-4378-ae2d-65a3f9863c15`: 2026-11-21 14:30 KST,
  언주역, 활성, verified=false, 남녀 가격 null, 원본 게시물 DfizQWZEiuA.
  익명 Data API에서도 같은 행이 HTTP 200으로 조회되어 앱 공개 읽기 경로를 확인했다.
- 기존 verified=true 행 `cb2e1e00-9ed9-41af-a01c-90e2cb72351b`의 10/31 13:30,
  언주역, 남녀 48,000원과 신청 URL은 변경되지 않았다.
- 최신 crawl_logs에 실제 success/found=1/new=1/updated=0을 확인했다.
  메일 발송 없는 `check_empty_crawls` 재검증에서 연숲 긴급 항목은 0건이다.
- 다음 점검은 서버의 0건 재발 여부를 확인해야 한다. 재발 시 이 로컬 재사용 경로는
  최신 원본과 저장 값을 대조한 후에만 사용한다. 정상 로그를 임의로 만들거나
  현재 1건 저장을 서버 자동 수집의 영구 복구라고 보고하지 않는다.
