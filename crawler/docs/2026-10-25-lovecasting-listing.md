# 러브캐스팅 0건 수집 복구

- 관리자 Gmail의 오늘 긴급 1건을 원문 확인했다. 4계정 중 다른 계정에는 관련 메일이 없다.
- 아침 실행 40140904263: 메뉴의 icon-list-item 요소가 카드 후보 36개를 채워
  실제 Elementor 일정 카드 탐색을 막았다. 원본 두 목록에는 미래 카드가 있는데
  파싱 0건으로 기록되는 것을 실제 HTML에서 재현했다.
- 날짜·시각이 정확히 한 회차인 카드만 선택하고 Elementor widget-wrap을 포함했다.
  서버 렌더링 HTML을 우선 읽고 필요할 때만 기존 브라우저 경로로 넘어간다.
- 성별 앞에 가격이 오는 새 표기를 직접 파싱해 남성 나이 뒤의 여성 가격을
  잘못 잡지 않게 했다. 한 성별 가격이 없으면 기존 값을 보존한다.
- 지난 카드를 임의로 내년 일정으로 넘기지 않는다. 한 목록이 비거나 실패하면
  collection_complete=false 및 DELETE_STALE=false로 기존 일정 삭제/잘못 마감을 막는다.
  오류 상세 페이지에서 이미지/가격을 가져오지 않게 HTTP 상태도 검사한다.
- 저장 없는 실제 scrape(): 8건. 커피 10/31·11/7·11/14·11/21 15:00,
  호프 같은 날짜 19:00. 남 50,000/여 20,000, 각 카드의 나이·지역과 대조했다.
  11/28은 기존 1개월 수집 범위 밖이라 제외했다.
- 기존 미검증 10/31 커피 행은 과거 17:00이었다. 현재 목록과 상세의 15:00이
  모두 일치함을 확인해 동일 id의 시각/회차 URL 두 필드만 정정했다.
  id/verified=false/기존 일시/기존 URL을 모두 조건으로 걸고 다른 값은 바꾸지 않는다.
  verified 행 전후 동일 검사 포함. 원본: https://lovecasting.co.kr/26-10-31-%ec%bb%a4%ed%94%bc/
- 회귀 검사 158개 통과. 카드끼리 값 섞임, 빈 가격, 지난 날짜, 부분 수집에서
  삭제 및 잘못 마감 방지, 유료 수집 없는 단독 재확인 분기를 포함한다.
- crawl.yml에 lovecasting_recheck 분기를 추가했다. 일반 수집/후속 알림/Apify는
  실행하지 않고 해당 스크래퍼 정상 저장 경로만 확인한다.
